006 - DEVICE TREE
==============================================================

Our DTS
-------
    projects/ROCKNIX/devices/RK3326/linux/dts/rockchip/
        rk3326-funnyplaying-rppocket.dts

It #includes rk3326-odroid-go.dtsi, which in turn includes rk3326.dtsi.
The Anbernic RG351M DTS (rk3326-anbernic-rg351m.dts) is the closest
sibling and was the template we started from.

What our DTS overrides on top of the parent dtsi
-------------------------------------------------
    1. Model + compatible
           model = "FunnyPlaying RetroPixel Pocket"
           compatible = "funnyplaying,rppocket", "rockchip,rk3326"

    2. Battery node
           3000 mAh design capacity, ocv-capacity-table-0 unchanged
           from the RG351M because the chemistry is the same.

    3. gpio-keys block
           18 buttons in three groups; pinctrl-0 = <&btn_pins>.
           See 010-input-mapping.txt and 011-rocker-mystery.txt.

    4. &pinctrl extension
           btns / btn_pins block listing all 18 button GPIOs as
           RK_FUNC_GPIO + pcfg_pull_up.  Mandatory on rockchip — the
           gpio framework doesn't auto-mux pins, so any button pin
           whose default function is some peripheral reads garbage
           without an explicit iomux entry.

    5. GPIO power-rail hogs (008-power-rails.txt)
           gpio0 RK_PA2  lcd-vspn-en      output-high
           gpio3 RK_PC3  lcd-vcc5v-en     output-high
           gpio3 RK_PC5  ns4150-amp-en    output-high
           Three rails that need to be HIGH for life-of-system.

    6. rk817 LDO regulator overrides (008)
           LDO_REG1 (added):  backlight2v8_supply  2.8 V always-on
           LDO_REG7 (revised): vcc_bl semantics now lcd2v8 at 2.8 V
                              (was 3.3 V on RG351M)
           LDO_REG8 (revised): vcc_lcd at 1.8 V (was 2.8 V on RG351M)

    7. &backlight power-supply override
           power-supply = <&backlight2v8>;
           Re-routes pwm-backlight to LDO_REG1 (the actual LED rail)
           instead of LDO_REG7.

    8. &internal_display override
           compatible = "jdi,lt031mdz4000";
           iovcc-supply = <&vcc_lcd>;
           vdd-supply   = <&vcc_bl>;
           rotation     = <0>;        (RG351M parent has 270; we
                                       cancel that because the RPPocket
                                       panel is mounted upright)

    9. &rk817_charger
           monitored-battery = <&battery>;
           Note: no current-sense resistor on this device, so charge
           current readback is not useful.

A vs B image groups
-------------------
projects/ROCKNIX/config.xml partitions the RK3326 device list into two
named groups, each producing its own SD image.  We belong to the 'a'
group (line 25):

    <a mkimage_options="dtb,bootscr,extlinux,uboot" fdt_type="fdtdir" fdt="/">
      <file>rk3326-anbernic-rg351m</file>
      <file>rk3326-anbernic-rg351v</file>
      <file>rk3326-funnyplaying-rppocket</file>     <- us
      <file>rk3326-gameconsole-r33s</file>
      ...
    </a>

The 'b' group is for Powkiddy RGB10X / RGB20S / etc. and has different
boot defaults.  The build emits a SEPARATE image per group, so always
flash target/...-a.img.gz on this device.

Adding our DTB to the kernel build
----------------------------------
The mainline kernel's RK3326 Makefile doesn't list our DTB by default.
We add it via:

    devices/RK3326/patches/linux/003-rk3326-funnyplaying-rppocket-dtb.patch

This is a one-line addition to arch/arm64/boot/dts/rockchip/Makefile.

Kernel config delta
-------------------
File: projects/ROCKNIX/devices/RK3326/linux/linux.aarch64.conf

We add a single line:

    CONFIG_DRM_PANEL_JDI_LT031MDZ4000=y

This pulls in the panel driver from our 002-panel patch (007-panel-driver.txt).
Built-in (=y) rather than a module so the panel is alive before any
module loading races kick in.

Inheritance chain (top to bottom)
---------------------------------
    rk3326-funnyplaying-rppocket.dts
        #include "rk3326-odroid-go.dtsi"
            #include <dt-bindings/gpio/gpio.h>
            #include <dt-bindings/input/input.h>
            #include <dt-bindings/leds/common.h>
            #include <dt-bindings/pinctrl/rockchip.h>
            #include "rk3326.dtsi"
                ... SoC-level stuff: clocks, IOMMU, VOP, DSI, USB, etc.

So our top-level DTS already has the input.h codes (BTN_DPAD_UP,
KEY_VOLUMEUP, etc.) and the pinctrl/rockchip.h pin macros (RK_PA0,
RK_FUNC_GPIO, &pcfg_pull_up) without further includes.
