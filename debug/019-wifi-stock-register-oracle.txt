2026-04-27 - Wi-Fi stock register oracle
========================================

Goal
----
Use the working stock image as the primary source for the remaining
RTL8188EUS enumeration problem.  ROCKNIX now matches the obvious stock
steady-state controls, but the Realtek USB device still does not appear.
The next useful evidence is a direct stock-working vs ROCKNIX-failing
comparison below the normal Linux device model.

Known state
-----------
Stock v1.1.3:

    - enumerates RTL8188EUS as USB 0bda:8179
    - uses DWC2 at ff300000
    - has RK817 LDO9/vcc_wifi enabled
    - has RK817 boost/otg_switch behavior for USB VBUS
    - has GPIO115/vcc5v_en_gpio out hi
    - does not use GPIO73/PB1 as a Wi-Fi regulator

ROCKNIX:

    - has vcc_wifi enabled at 3300mV
    - has otg_switch enabled at 5000mV and feeding ff300000.usb-vbus
    - has GPIO115/vcc5v-en out hi
    - has DWC2 root hub 1d6b:0002
    - does not enumerate 0bda:8179

Decision
--------
Stop guessing additional DTS topology.  Instrument stock and ROCKNIX with
the same passive low-level capture:

    - /proc/iomem filtered for USB/PHY/GRF ranges
    - /sys/kernel/debug/clk/clk_summary filtered for USB/PHY clocks
    - /sys/kernel/debug/pinctrl/*/pinmux-pins filtered for USB/gpio2/gpio3
    - /sys/kernel/debug/gpio
    - regulator summary
    - devmem read-only windows:
        - 0xff010000 PMU GRF
        - 0xff140000 GRF
        - 0xff2c0000 USB2 PHY GRF
        - 0xff300000 DWC2 core
        - 0xff300400 DWC2 host registers

These reads must be passive.  Do not write MMIO registers from the debug
hook.

Implementation
--------------
Updated:

    debug/stock-custom_start.sh
    debug/pre.sh

Both scripts now contain a matching dump_lowlevel_usb_state helper.  The
ROCKNIX hook captures:

    - rocknix-early
    - rocknix-late-before-rebind
    - rocknix-late-after-rebind

The stock hook captures the same low-level sections in every existing
stock snapshot:

    - early_before
    - before_2s
    - before_10s
    - before_40s
    - after
    - after_10s

Expected test
-------------
First capture ROCKNIX-failing state by installing the updated hook on the
current ROCKNIX card without reflashing:

    sudo ./debug/pre.sh /dev/<sdX>

Boot, wait at least 3 minutes, shut down, reinsert the card, and inspect
the refreshed rppocket-debug.txt and rppocket-late.txt.

Then refresh the stock debug image with the updated stock-custom_start.sh,
flash it, confirm stock Wi-Fi still scans, reinsert the card, and compare
the low-level sections against ROCKNIX.

Refined conclusion:
    Timing alone is not enough.  A previous ROCKNIX experiment already
    delayed the first DWC2 root-hub probe until approximately the same
    boot window as stock and still did not enumerate 0bda:8179.

    The strongest remaining stock-derived lead is GPIO115 ownership and
    sequencing.  Stock does not hold GPIO115 high with a gpio-hog.  The
    vendor panel driver requests the panel vcc5v_en_gpio, drives it low
    at probe, then drives it high during panel prepare before DWC2 sees
    the Realtek device.  ROCKNIX currently holds GPIO115 high from boot
    with a gpio-hog, and the clean JDI panel driver does not know about
    the vendor vcc5v_en_gpio property.

Next experiment:
    Move GPIO115 from a gpio-hog into the JDI panel driver as a standard
    optional enable-gpios line:

        - add enable_gpio to panel-jdi-lt031mdz4000
        - request "enable" with GPIOD_OUT_LOW at probe
        - set enable high during panel prepare
        - set enable low during unprepare/failure
        - add enable-gpios = <&gpio3 RK_PC3 GPIO_ACTIVE_HIGH> to the
          RPPocket panel node
        - remove the vcc5v-en GPIO hog

    Success condition is still Realtek USB enumeration as 0bda:8179 and
    wlan0 creation.  A display regression would also be important because
    this changes panel power sequencing.

Conclusion:
    This closes the stock-register-oracle DTS/config guess phase.  The
    stock-derived obvious controls are now either matched or tested:

        - vcc_wifi
        - boost/otg_switch
        - GPIO115 panel enable sequencing
        - no explicit DWC2 vbus-supply

        - delayed DWC2 rebind/probe timing

    broad DTS guess.  Since the original stock source can now be compiled
    locally, switch to instrumented stock-kernel experiments that explain
    why stock sees the downstream RTL8188EUS connect and ROCKNIX does not.
