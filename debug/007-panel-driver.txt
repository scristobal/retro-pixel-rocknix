007 - PANEL DRIVER (JDI LT031MDZ4000)
==============================================================

What
----
3.1" 720x720 IPS MIPI-DSI panel, 2-lane, used on the RetroPixel Pocket
in 'natural' (non-rotated) orientation.

There is no public datasheet — the only reference we have is the init
sequence in jamwu's RPI-LCD-LT031MDZ4000 driver for Raspberry Pi:

    https://github.com/jamwu/RPI-LCD-LT031MDZ4000

Cross-checking byte-for-byte against the RPPocket BSP's panel-simple.c
match confirmed the panel ID.

Where the driver lives
----------------------
    projects/ROCKNIX/devices/RK3326/patches/linux/
        002-panel-jdi-lt031mdz4000.patch

A kernel patch that adds:

    drivers/gpu/drm/panel/panel-jdi-lt031mdz4000.c
    drivers/gpu/drm/panel/Kconfig    (new symbol)
    drivers/gpu/drm/panel/Makefile   (new file entry)

Built-in via CONFIG_DRM_PANEL_JDI_LT031MDZ4000=y in
linux.aarch64.conf.

Driver shape
------------
    compatible:        "jdi,lt031mdz4000"
    DSI lanes:         2
    DSI mode flags:    MIPI_DSI_MODE_VIDEO
                       MIPI_DSI_MODE_VIDEO_BURST
                       MIPI_DSI_MODE_LPM
                       MIPI_DSI_MODE_NO_EOT_PACKET    (commit c725b1123d)
                       MIPI_DSI_CLOCK_NON_CONTINUOUS  (commit c725b1123d)

The last two flags were necessary on RK3326's dw-mipi-dsi: without
them the panel would respond to the prepare() init sequence (we saw
kernel logs reach 'prepare: done') but stay dark.

Init sequence
-------------
A long DCS / generic-write sequence executed inside .prepare():
sets gamma, panel timings, power-on registers, then exits sleep mode
and turns display on.  Sequence is byte-identical to jamwu's RPi
driver — see the .c file for the full table.

Allocation pattern
------------------
We use the older devm_kzalloc + drm_panel_init pattern:

    panel = devm_kzalloc(dev, sizeof(*panel), GFP_KERNEL);
    drm_panel_init(&panel->base, dev, &panel_funcs, DRM_MODE_CONNECTOR_DSI);

NOT devm_drm_panel_alloc (which doesn't exist on kernel 6.12).  This
is the same idiom the elida-kd35t133 driver uses; copy that one if
you ever need to write another panel driver for this kernel rev.

Power rails
-----------
Two regulator-supply consumers:

    iovcc-supply = <&vcc_lcd>;     1.8 V (rk817 LDO_REG8 on RPPocket)
    vdd-supply   = <&vcc_bl>;      2.8 V (rk817 LDO_REG7 on RPPocket)

The labels '&vcc_lcd' and '&vcc_bl' are inherited from the RG351M dtsi
where they meant something else.  The labels stay (they are phandle
names) but the underlying voltages are now correct for RPPocket.  See
008-power-rails.txt for the full LDO swap story.

Reset / enable
--------------
Panel reset is done via the DSI-host's reset GPIO (gpio3 RK_PC0 in the
inherited dtsi); we do not override it.

Backlight is a separate pwm-backlight node that we re-supply (008).

Common debug logs
-----------------
On a healthy boot you'll see in dmesg:

    [    1.085846] backlight2v8_supply: supplied by vcc3v8_sys
    [    1.086103] backlight2v8_supply: Bringing 1000000uV into 2800000-2800000uV
    [    1.088377] backlight2v8_supply: 2800 mV, enabled
    [    1.199130] pwm-backlight backlight: Looking up power-supply from device tree
    [    1.203901] panel-jdi-lt031mdz4000 ff450000.dsi.0: Looking up vdd-supply from device tree
    [    1.204096] panel-jdi-lt031mdz4000 ff450000.dsi.0: Looking up iovcc-supply from device tree
    [    1.205386] rockchip-drm display-subsystem: bound ff460000.vop (ops ...)
    [    1.205905] rockchip-drm display-subsystem: bound ff450000.dsi (ops ...)
    [    1.267702] panel-jdi-lt031mdz4000 ff450000.dsi.0: prepare: begin
    [    1.707957] panel-jdi-lt031mdz4000 ff450000.dsi.0: prepare: done

If you see 'prepare: done' but the screen is black, suspect:
    - Wrong rotation (panel is on but you're looking at the back)
    - Backlight LED rail off (008)
    - Panel power gate not asserted (008)
    - DSI mode flags wrong (commit c725b1123d)

Rotation
--------
    rotation = <0>;  in the DTS

The parent rk3326-anbernic-rg351m DTS uses rotation=270 because the
RG351M panel is physically mounted sideways.  RPPocket's panel is
upright, so we cancel that.  If you see ROCKNIX UI 90 degrees off,
it's almost always this property.
