2026-08-02 - Resolve integration build failures
------------------------------------------------
Hypothesis:
    Failures introduced by independently changed upstream and topic
    code should be resolved at their ownership boundary, without
    altering verified RPPocket hardware behavior.

Changes:
    1. Kernel USB2 PHY callback collision:

       The RPPocket vendor patch and new upstream PX30S backport both
       defined rk3328_usb2phy_tuning() and assigned it to the same PHY
       configuration. Added:

           projects/ROCKNIX/devices/RK3326/patches/linux/
           034-rppocket-compose-rk3328-usb2phy-tuning.patch

       It renames the earlier callback to
       rk3328_usb2phy_vendor_tuning(), invokes it from the new composite
       callback, and leaves one callback assignment. This preserves the
       known RPPocket GRF writes before applying PX30S-only tuning.

    2. RenderDoc dependency declaration:

       RenderDoc 1.44 now checks for xcb-keysyms, but its package did
       not depend on xcb-util-keysyms. Added that package dependency.

    3. Stale local LTO cache:

       VLC found a libx264.a built with the pre-refresh GCC 14 LTO
       format while the refreshed toolchain expected GCC 15. Cleaned
       only x264 and VLC through the package-clean targets, then resumed
       the cached full build. No source workaround was required.

Observed result:
    Kernel, RenderDoc, x264, VLC, Rust, emulators, and final image
    generation all completed successfully.
