005 - U-BOOT AND BOOT FLOW
==============================================================

RK3326 boots in two stages, and ROCKNIX uses a very specific
combination on the 'a' device group:

Stage 1 (TPL + SPL) — Hardkernel u-boot-legacy
-----------------------------------------------
    Source:  projects/ROCKNIX/devices/RK3326/packages/u-boot-legacy/
    Role:    Initial DRAM init, power-up, reads SARADC channel 0 to
             identify the device, sets a 'hwrev' env var, then chains
             into stage 2.
    Why this one: ROCKNIX inherits this from JELOS / 351ELEC; the
             TPL/SPL blobs are calibrated for the RK3326 SDRAM timings
             on these handhelds and a clean mainline TPL doesn't
             always train DRAM correctly here.

Patch we add: hwrev table
-------------------------
File:
    projects/ROCKNIX/devices/RK3326/packages/u-boot-legacy/patches/
        0001-hwrev-recognize-funnyplaying-rppocket.patch

It teaches cmd/hwrev.c to map ADC channel-0 readings in the range
380..420 to:

    hwrev = "rppocket"
    dtb_name = "rk3326-funnyplaying-rppocket.dtb"

Without this patch, our ADC reading (~399) falls through to the
"engineer sample" default, which expects rk3326-odroidgo2-linux.dtb to
exist on the boot partition.  That symptom looks like: cold boot stops
at a dual blink of the charging LED and "dtb load fail" if you have
serial.

Engineer-sample fallback
------------------------
In addition to the hwrev patch, projects/ROCKNIX/bootloader/mkimage
creates two compatibility aliases at image assembly time:

    rk3326-odroidgo2-linux.dtb     <- copy of rk3326-anbernic-rg351m.dtb
    rk3326-odroidgo2-linux-v11.dtb <- same

These are placeholders — if u-boot-legacy ever decides we are an
"engineer sample" (which it shouldn't, given the hwrev patch), it has
SOMETHING to load instead of failing.  The RG351M DTB will likely not
fully boot RPPocket but it gets us past stage 1.

Stage 2 — mainline u-boot v2025.10
-----------------------------------
    Source:  projects/ROCKNIX/devices/RK3326/packages/u-boot/
    Role:    Runs an extlinux-style boot script that picks the right
             DTB based on hwrev / ADC, then loads kernel + DTB +
             initramfs (we don't use initramfs; just kernel + DTB).

Patch we add: a_boot.ini
------------------------
File:
    projects/ROCKNIX/devices/RK3326/packages/u-boot/config/a_boot.ini

Two surgical edits (commits e29a503290 and 3a158d5265):

  1. Map hwrev='rppocket' to numeric ADC 399 — a direct rule that
     prefers the symbolic hwrev over reading ADC again, useful when
     stage 1 already fingerprinted us.

  2. Place the rppocket ADC branch BEFORE the open-ended RG351V
     catch-all (itest.w ${adc} < 541).  Otherwise our 399 falls into
     the RG351V range first and we boot the wrong DTB.  This is a
     fragile bit of script — if you change the ADC table, double-check
     the order of branches.

Strip FDTOVERLAYS
-----------------
projects/ROCKNIX/devices/RK3326/packages/u-boot/package.mk has a small
sed step that strips FDTOVERLAYS from the generated extlinux.conf.rppocket
because we don't ship overlays for RPPocket and a stale FDTOVERLAYS
line aborts u-boot's load.

DTB selection result, end-to-end
--------------------------------
    cold boot
      -> u-boot-legacy reads SARADC ch0 = ~399
      -> matches range 380..420 in hwrev table
      -> sets hwrev=rppocket, dtb_name=rk3326-funnyplaying-rppocket.dtb
      -> hands off to mainline u-boot
      -> mainline u-boot reads hwrev=rppocket
      -> a_boot.ini sets fdtfile=rk3326-funnyplaying-rppocket.dtb
      -> extlinux.conf loads kernel + that DTB
      -> kernel boots

ROM-vs-flash sanity
-------------------
The image we build is *bootable from microSD only* in this repo.  We
do not currently produce an "install to internal" image, because the
RPPocket SD-only architecture (no eMMC) means there's nowhere to
install to.

Image size
----------
The two emitted -a/-b images are ~1.5 GB each.  The actual SD will be
expanded on first boot to fill the card via projects/ROCKNIX/packages/
sysutils/busybox/scripts/fs-resize.  pre.sh --flash pre-grows it on the
host before first boot so debug hooks have room to write.
