009 - AUDIO
==============================================================

Topology
--------
The RK3326's i2s controller talks to the rk817's internal codec via
ff070000.i2s-rk817-hifi.  The rk817 has two output pin-pairs:

    HPOL / HPOR     headphone output
    SPKO            single-ended speaker output

On RPPocket the SPKO pin is NOT WIRED to anything.  The internal
loudspeaker is driven from the codec's HP outputs (HPOL/HPOR)
through an external NS4150 class-D amplifier.

This is the same audio topology as the Anbernic RG351M, and our quirk
is modelled directly on the RG351M one (which we cross-checked).

ALSA mixer state (snapshot from a working device)
-------------------------------------------------
    numid=1  CARD     'Headphones Jack'        (BOOLEAN, jack-detect)
    numid=2  MIXER    'Master Playback Volume' 0..255
    numid=3  MIXER    'Master Capture Volume'  0..255
    numid=4  MIXER    'Mic Capture Gain'       0..15
    numid=5  MIXER    'Playback Mux'           ENUMERATED 'HP' or 'SPK'

The codec exposes a 2-position mux that selects whether playback goes
to the HP path or the SPK path.  Default after boot is 'SPK'.  On
this device that means: playback by default lands on SPKO, which is
the unwired pin, so audio is silent.

Quirk
-----
File:
    packages/hardware/quirks/devices/FunnyPlaying RetroPixel Pocket/
        001-device_config

    cat <<EOF >/storage/.config/profile.d/001-device_config
    # Device Features
    DEVICE_PLAYBACK_PATH="Playback Mux"
    DEVICE_PLAYBACK_PATH_SPK="HP"
    DEVICE_PLAYBACK_PATH_HP="SPK"
    DEVICE_VOLUME="100"
    DEVICE_BATTERY_LED_STATUS="false"
    DEVICE_TEMP_SENSOR="/sys/devices/virtual/thermal/thermal_zone0/temp"
    DEVICE_MMC_EJECT="false"
    EOF

The SPK/HP swap is the key bit:

    "speaker mode" -> sets Playback Mux to HP   (= SPKO is dead, route to HP)
    "headphone mode" -> sets Playback Mux to SPK (= no real-world meaning,
                        but ROCKNIX expects to flip the mux when a
                        headphone is detected; we flip it the other way)

We trust ROCKNIX's headphone-jack hotplug script to use these values.
On insert, it swaps to DEVICE_PLAYBACK_PATH_HP=SPK; that disables the
HP-routed-to-NS4150 path.  Most users will never hotplug headphones
on this device, so the speaker case is the dominant code path.

Volume init quirk
-----------------
File:
    packages/hardware/quirks/devices/FunnyPlaying RetroPixel Pocket/
        050-volume

    #!/bin/sh
    . /storage/.config/profile.d/001-device_config
    amixer -c 0 set "Master" "${DEVICE_VOLUME}%"

Sets ALSA Master volume to 100% on each boot.  ROCKNIX's audio
subsystem layers its own per-application volume control on top of a
fixed 100% codec gain, which is why we don't want to touch the
codec gain at runtime.

NS4150 amp enable
-----------------
The NS4150 is gated on/off by gpio3 RK_PC5 (active-high).  Without
that GPIO pulled high, the speaker emits NOTHING regardless of mixer
state.  See 008-power-rails.txt — we hog the pin to output-high so
it is enabled before any sound subsystem comes up.

Headphone jack
--------------
The 3.5 mm jack is wired to a detection GPIO (gpio2 RK_PA22, taken
from the inherited dtsi as 'hp-det').  It produces an EV_SW SW_HEADPHONE_INSERT
event on the rk817_int Headphones input device (event1).  ROCKNIX's
audio quirk script listens for this and swaps the Playback Mux.

Headphone detection pinctrl
---------------------------
The hp-det pin already has its own pinctrl in the parent dtsi, so we
do NOT include it in our btn_pins block.  Including it would attempt
to dual-claim the pin and fail.

Verifying on a running device
-----------------------------
    aplay -l                                # should list 'rk817int' card 0
    amixer -c 0 contents                    # mixer 5 'Playback Mux' should be 'HP'
    cat /sys/kernel/debug/gpio | grep amp   # gpio3 RK_PC5 should be 'out hi'

A 1-second sine tone the early-boot debug hook used to issue at boot
was removed (commit e388f84fcb) once the quirk reliably routed the
mixer correctly.
