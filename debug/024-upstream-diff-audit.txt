024 - RPPocket upstream-diff production audit
==============================================

Purpose
-------
Audit the complete topic-branch delta from its upstream merge base
cf5767ee0ae6ce7b9c1850ce3ecc7dad1888644b. Remove obsolete bring-up
instrumentation, misleading candidate metadata, unused hardware descriptions,
and unrelated changes without discarding validated RPPocket support or the
historical evidence under debug/.

Scope reviewed
--------------
Production and packaging files:

* ROCKNIX device registration and both U-Boot selection paths;
* the complete RPPocket DTS and RK3326 kernel configuration delta;
* panel, USB2 PHY, DWC2, RK817, firmware-policy, power-domain, and Mali patches;
* controller databases and RetroArch profile;
* RPPocket audio, volume, logind, backlight, and suspend-inhibitor quirks;
* the RenderDoc dependency adjustment needed to build the refreshed upstream
  baseline.

Repository support files:

* AGENTS.md;
* debug/001 through debug/023 and debug/current_state.txt;
* debug/pre.sh, register-diff.sh, the stock-image oracle helper, and retained
  stock/ROCKNIX evidence captures.

Findings and changes
--------------------

1. RPPDBG and panel lifecycle logging were obsolete.

   Removed the two instrumentation-only kernel patches that traced DWC2 and
   USB2PHY state, and removed unconditional panel prepare/unprepare/probe/remove
   dev_info() messages. Normal error reporting remains.

2. Two USB changes had production behavior hidden behind experiment names.

   Renamed and rewrote their metadata as the stock DWC2 TOUTCAL quirk and the
   stock USB2PHY power-on sequence. Both remain narrowly RPPocket-scoped and
   retain behavior already exercised across cold boot and repeated DWC2
   unload/reload suspend cycles. The source-backed RK3328 PHY tuning remains and
   composes with the upstream-refresh PX30S tuning callback.

3. Temporary DWC2 host-only policy was still present.

   Kept DWC2 modular for the validated sleep-hook unload/reload path, but
   restored the kernel's normal dual-role configuration. The RPPocket DTS still
   selects its working controller topology.

4. Unvalidated input mappings were exposed.

   Removed the PA0/PA1/PB2 brightness entries and gpio3 PB7 centre-button entry.
   They had produced no useful action. The validated twelve game controls and
   gpio3 PD3/PC4 volume up/down keys remain.

5. RK817 support exposed unused bring-up GPIOs.

   Reduced patch 028 and the DTS to the SLP pin states actually required by the
   validated suspend sequence. Removed unused TS/GT GPIO muxes, the unused PMIC
   power-off pinctrl state, and the RK817 GPIO-controller exposure. Added managed
   cleanup for the vendor-derived pinctrl child device. Suspend/reset states and
   patch 039's validated polarity ordering remain unchanged.

6. Obsolete active diagnostic workflows remained in debug/pre.sh.

   Removed callback-walker, pm_test, freeze, deep-suspend, watchdog/ramoops,
   DWC2-rebind, stock-init, and GPIO-scan modes and generated services/scripts.
   Release mode now also removes artifacts left by those historical versions.
   The current power-slider regression modes, generic broad capture, stock-image
   oracle, ROM/PICO-8 installation, and --release mode remain. Historical
   decision logs and captured evidence remain intentionally.

7. Release and inhibitor cleanup needed hardening.

   Release mode now removes all persisted rppocket-*.log captures and obsolete
   PM harness files. The suspend inhibitor removes a stale PID file safely and
   signals an old process only when both its comm and --who=rppocket-sleep
   command-line identity match.

8. Unrelated branch changes existed.

   Restored .gitignore and projects/ROCKNIX/bootloader/mkimage to the upstream
   versions and removed the obsolete SDWire helper. SDWire is prohibited by the
   project workflow.

9. Patch descriptions and active state documentation were stale.

   Removed candidate/temporary wording, stale statistics, old timestamps,
   malformed mail footers, and the pre-validation warning from the validated
   firmware-policy patch. Updated current_state.txt and release documentation.

Intentionally retained
----------------------

* The exact stock BL31 rockchip,sleep-debug-en=<1> setting remains for this
  gate. It is a firmware policy value from the compiled factory DTB, not an
  RPPDBG kernel trace. Changing it is a separate hardware-facing variable and
  must be tested only after this cleanup candidate passes.
* GPIO3_PC2 output-low remains because the factory init explicitly establishes
  that state and every validated production image retained it.
* CONFIG_RTL8XXXU_UNTESTED=y remains because that Kconfig gate is required for
  the hardware-validated RTL8188EUS driver path; "UNTESTED" is the upstream
  symbol name, not the status of this port.
* Standard RK3326 ROCKNIX options such as CONFIG_PM_DEBUG, CONFIG_PM_SLEEP_DEBUG,
  CONFIG_DYNAMIC_DEBUG, CONFIG_DEBUG_FS, CONFIG_PSTORE_RAM, and the upstream
  debug-package selection were already present at the merge base. This audit
  does not create a board-local kernel configuration fork merely to remove
  shared facilities.
* The RenderDoc xcb-util-keysyms dependency remains because it fixes a real
  dependency omission encountered while building the refreshed upstream tree;
  it does not add RenderDoc to an image that upstream would not otherwise build.
* Numbered decision logs, stock/ROCKNIX captures, register-diff.sh, and the stock
  custom_start oracle are evidence and development tools, not shipped runtime
  hooks. --release removes writable-card diagnostics.

Pending hardware gate
---------------------

This candidate is built but not yet hardware-validated. Do not commit it yet.
Prepare a production-clean card with:

    sudo debug/pre.sh --flash --release /dev/sdb

Before flashing, verify the image path still hashes to the image-A value above.
Then perform one focused regression pass:

1. cold boot to the normal UI;
2. confirm display, controls, volume up/down, audio, and Wi-Fi;
3. perform one short slider suspend/resume and confirm full backlight-off,
   successful wake, restored Wi-Fi, and no immediate suspend replay;
4. perform the normal approximately five-second orderly poweroff to finish.

After reinserting the card, inspect it directly before accepting the candidate.
Only after this gate passes should rockchip,sleep-debug-en be considered as a
separate isolated firmware-policy cleanup.

The prepared card was independently mounted read-only before boot. KERNEL,

matched. STORAGE had no debug hook, experiment marker, service, symlink,

The user then confirmed that cold boot, display, controls, volume, audio,

Decision:

    Proceed with exactly one additional hardware-facing variable: change the
    RPPocket BL31 sleep-debug control from the stock value 1 to explicit 0.
