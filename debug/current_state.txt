Agent workflow
--------------
[RULE] Read 013-agent-workflow.txt before making changes.

[RULE] All RPPocket commits stay on retropixel-pocket-support.  Do not
       commit RPPocket work on next.

[RULE] Commit messages carry the detailed per-change debug log:
       observed problem, hypothesis, change made, and test requested.

       current state and stable findings: what works, what does not,
       open questions, and the next concrete test.  Use topic-specific
       decision logs, such as 014-wifi-decision-log.txt, for active
       unresolved trial-and-error.

[RULE] After a change, ask the user to run debug/pre.sh with --flash
       only if a fresh image/rootfs is required.  Otherwise ask for
       plain debug/pre.sh.

[RULE] After device testing, expect the user to insert the SD into the
       host and tell the agent it is inserted.  The agent should mount
       the SD and inspect the full boot/storage logs directly before
       the next hardware-facing edit.

[RULE] Do not use SDWire3 for this project.  It is unreliable.  Use the
       manual debug/pre.sh flash, device test, and SD reinsertion flow.

Open questions
--------------
1.  Are the rocker switches actually wired to gpio2 PA2 and PA4 on
    this device, or is the BSP's mention of those GPIOs a leftover
    from the RG351MP design that does not apply to RPPocket
    physically?  Latest evidence points to PA2/PA4 being leftovers:
    the original RPPocket DTS identifies volume up/down as gpio3
    PD3/PC4 instead.

2.  Does the brightness rocker actually have three distinct
    switches, and should ROCKNIX bind the observed PA0/PA1/PB2
    contacts to a brightness action directly?  The vendor behavior
    points instead to Fn + volume, but the Fn GPIO from the vendor
    tree has not been observed firing.
