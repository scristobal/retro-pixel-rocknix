Stuff that's broken or unfinished
---------------------------------
[BUG]  Volume and brightness rockers are mismapped.  Each has 3
       physical actions (up tilt / down tilt / centre press).  4 of
       the 6 actions fire SOMETHING in repeated tests, but the
       physical action -> GPIO mapping is not consistent between
       test sessions and real-use feedback.  Specifically: gpio2 PA2
       and PA4 never fired any event in two consecutive captures.
       See 011-rocker-mystery.txt for the full saga and the
       outstanding 6-action test that would resolve it.

[TODO] Wi-Fi.  The device has a Realtek RTL8188EUS USB Wi-Fi module.
       The mainline 'r8188eu' staging driver should cover it, but is
       not currently included in our linux.aarch64.conf.  Without
       Wi-Fi, the device has no off-cable network access and we have
       no way to ssh in for live debugging — every diagnostic round
       requires a flash + power cycle + SD pull.

[TODO] Power slider.  The hardware-side slider is wired through
       rk805_pwrkey (verified via /proc/bus/input/devices); a long
       slide presumably triggers PMIC poweroff.  Behaviour beyond
       'pwrkey' has not been verified, and there is no investigation
       yet of whether ROCKNIX's expected suspend/resume hooks fire.

[TODO] Battery LED.  The 001-device_config quirk sets
       DEVICE_BATTERY_LED_STATUS="false" because the LED behaviour
       on RPPocket has not been characterised.  The device has a
       red+green dual LED; only red has been seen lit (at boot).

[TODO] Test additional emulators.  Only Game Boy has been verified
       end-to-end (system shows up + ROM list populates).  No game
       has been launched into RetroArch yet.

Open questions
--------------
1.  Are the rocker switches actually wired to gpio2 PA2 and PA4 on
    this device, or is the BSP's mention of those GPIOs a leftover
    from the RG351MP design that does not apply to RPPocket
    physically?  Concrete way to find out: probe the rocker pins
    with a multimeter while a switch is held.  Without that, see
    011-rocker-mystery.txt for the next-best diagnostic step.

2.  Does the brightness rocker actually have three distinct
    switches, or is the user describing a 2-switch component?
    Resolved by the same physical inspection or by the 6-action
    re-test in 011.

How to resume work
------------------
1.  Boot the device with the current image and try the 6 rocker
    actions described at the bottom of 011-rocker-mystery.txt.
    Capture the visible reaction of each.
2.  Edit the rocker entries in the gpio-keys block of
    rk3326-funnyplaying-rppocket.dts to match what was learned.
3.  Rebuild with make docker-RK3326, flash with debug/pre.sh --flash.
4.  Verify rockers behave as expected.
5.  Add r8188eu to linux.aarch64.conf and to ADDITIONAL_DRIVERS
    if needed; rebuild; verify Wi-Fi.
6.  Keep commits on retropixel-pocket-support.  Rebase or merge over
    upstream/next when needed, then push the topic branch to origin
    and clean up the commit log if helpful for a future upstream PR.
