2026-04-26 - Board inspection identifies USB RTL8188EUS
------------------------------------------------------
Hypothesis:
    The Wi-Fi chip is USB, not SDIO.  Previous SDIO-focused experiments
    could not make progress because the board does not use the suspected
    RTL8189FS/RTL8189ES SDIO path.

Evidence used before changing code:
    User opened the device and reported the Wi-Fi marking:

        Realtek RTL8188EUS - E210631 GE40

    Factory/source evidence agrees with this:

        - original vendor module exists:
          rockchip_wlan/rtl8188eu/8188eu.ko
        - modinfo aliases include:
          usb:v0BDAp8179
          usb:v0BDAp0179
        - original source usb_intf.c marks 0x0BDA:0x8179 as 8188EUS
        - original RetroPixel options included RTL8188EU

    ROCKNIX RK3326 already builds the in-kernel rtl8xxxu driver:

        CONFIG_RTL8XXXU=m

    but older/less-tested Realtek USB IDs are disabled:

        # CONFIG_RTL8XXXU_UNTESTED is not set

Code/image change:
    Enabled:

        CONFIG_RTL8XXXU_UNTESTED=y

    This keeps the first USB Wi-Fi test small and uses the existing
    in-kernel driver before porting the vendor 8188eu driver.

Build verification:
    Built ROCKNIX-RK3326.aarch64-20260426 successfully.

    Verified in the build output:

        CONFIG_RTL8XXXU=m
        CONFIG_RTL8XXXU_UNTESTED=y

    Verified image contents:

        /usr/lib/kernel-overlays/base/lib/modules/6.12.79/kernel/drivers/net/wireless/realtek/rtl8xxxu/rtl8xxxu.ko
        /usr/lib/kernel-overlays/base/lib/firmware/rtlwifi/rtl8188eufw.bin

Exact test requested:
    Build and flash a new image.  Boot with the device closed or open,
    then test Wi-Fi scanning from the settings UI.

Observed result from mounted SD logs:
    Pending.

Decision / next step:
    If this still does not scan, inspect mounted logs for:

        - whether USB enumerates 0bda:8179 or 0bda:0179

    If USB enumerates but rtl8xxxu is not sufficient, port or package
