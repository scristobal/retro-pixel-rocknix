2026-04-26 - Start over from a blank board description
------------------------------------------------------
Hypothesis:
    The main bring-up risk is the inherited board file, not a single
    missing property.  The current RPPocket DTS inherited:

        #include "rk3326-odroid-go.dtsi"

    That imported Odroid/RG351 board policy for PMIC rails, IO domains,
    SDMMC, USB, backlight, panel skeleton, sound, and miscellaneous
    GPIOs.  Factory RPPocket source instead describes a standalone
    board based on rk3326.dtsi / rk3326-linux.dtsi.

Evidence:
    Several hardware tests found that inherited assumptions were wrong
    or suspect:

        - RPPocket LDO_REG1/7/8/9 semantics differ from inherited
          Odroid/RG351 rails.
        - Factory sets both vccio1 and vccio2 to vccio_sd, while the
          inherited board used vccio1 from vcc_3v3.
        - Wi-Fi SDIO never enumerated across multiple incremental
          inherited-board overrides.
        - Factory SDIO/PMIC/panel GPIO descriptions are board-specific.

Change:
    Replace the RPPocket DTS include chain:

        old: #include "rk3326-odroid-go.dtsi"
        new: #include "rk3326.dtsi"

    Recreate explicit RPPocket board nodes for:

        - battery
        - pwm backlight and JDI panel
        - gpio-keys from the factory joypad pin map
        - rk817 PMIC/regulators using RPPocket rail names/voltages
        - vccio1/vccio2 both supplied by vccio_sd
        - SDMMC from factory shape
        - SDIO from factory shape
        - confirmed GPIO hogs for LCD bias and audio amp
        - USB host power through GPIO3 PC3

Build:
    First build failed at DTS compile:

        Label or path bus_apll not found

    This label exists in the factory BSP context but not in ROCKNIX's
    mainline rk3326.dtsi.  Removed the unsupported &bus_apll block and
    kept the standard &dmc center-supply wiring used by other ROCKNIX
    RK3326 board files.

Decision:
    Rebuild after removing &bus_apll.


2026-04-26 - Clean DTS build succeeds
-------------------------------------
Hypothesis:
    A standalone RPPocket DTS can compile in ROCKNIX if it only uses
    labels and bindings present in ROCKNIX's mainline RK3326 DTS tree.

Change:
    Removed the factory-only &bus_apll block.  Kept standard RK3326
    clock assignment and DMC center-supply wiring.

Build:
    make docker-RK3326 completed successfully.

    Generated images:

        target/ROCKNIX-RK3326.aarch64-20260426-a.img.gz
        target/ROCKNIX-RK3326.aarch64-20260426-b.img.gz

    Checksums observed locally:

        f5a14576d92bba5a2cd095e90c9d14853ec6342f80a2ba25ad913e4ec7ccd5a0  target/ROCKNIX-RK3326.aarch64-20260426-a.img.gz
        1af7ae1c2b2a7e861a1396ef8b4814691644d292405f79f87473676322953372  target/ROCKNIX-RK3326.aarch64-20260426-b.img.gz

DTB verification:
    Decompiling the built DTB confirms the main clean-DTS assumptions:

        - compatible is funnyplaying,rppocket, rockchip,rk3326
        - no Odroid/RG351 board include is present in the source DTS
        - no wifi-pwrseq node is present
        - no non-removable SDIO flag is present
        - vccio1-supply and vccio2-supply both point to vccio_sd
        - SDIO is mmc@ff380000 with supports-sd, cd-gpios on gpio3 PB6,
          vqmmc-supply = vccio_sd, and vmmc-supply = vcc_sd
        - LDO_REG5 is vccio_sd at 1.8V
        - LDO_REG6 is vcc_sd at 3.3V
        - LDO_REG9 is vcc_wifi at 3.3V

    A reset-gpios property remains in the DTB, but it belongs to the
    MIPI panel node, not to Wi-Fi/SDIO.

Exact test requested:
    Flash the new image and test whether the system still reaches the
    ROCKNIX UI.  If it boots far enough, check:

        - display orientation and backlight
        - D-pad, A/B/X/Y, Start, Select, L/R
        - volume up/down
        - audio output
        - PICO-8 launch
        - Wi-Fi scan

Observed result from mounted SD logs:
    User reported no regressions after flashing the clean-DTS image.
    Wi-Fi still does not work / no scan results.

    Mounted SD verification:

        - /run/media/samu/ROCKNIX/rk3326-funnyplaying-rppocket.dtb
          matches the build output DTB byte-for-byte:
          f9d61f2053baf618d8712673673344145c2dec800a9f3ed1c0024c2e4d7b66b2
        - dmesg reports:
          Machine model: FunnyPlaying RetroPixel Pocket
        - kernel command line includes:
          uboot.hwid_adc=a,rppocket
        - decompiled SD DTB has:
          compatible = "funnyplaying,rppocket", "rockchip,rk3326"
          model = "FunnyPlaying RetroPixel Pocket"
          no wifi-pwrseq node
          no non-removable flag on SDIO
          SDIO at mmc@ff380000 with supports-sd and gpio3 PB6 card detect
        - extlinux lists FDTDIR / and FDTOVERLAYS /overlays/mipi-panel.dtbo,
          but the boot partition contains no mipi-panel.dtbo file, so no
          RG351/R36S-style panel overlay is present.

    Remaining inherited/shared pieces are the normal RK3326 bootloader
    selection machinery and the presence of other device DTBs in the
    generic multi-device boot partition.  The selected runtime DTB is
    the RPPocket DTB, not RG351/Odroid.

Decision / next step:
    Clean DTS direction is validated for non-regression but does not
    solve Wi-Fi.  Continue Wi-Fi from first principles using the
    RPPocket DTB/logs rather than treating the board as RG351/Odroid.
    Do not commit until the user explicitly requests it.
